# Dependency access inventory and assumptions

Review date: 2026-11-18. Base: `018b4cadb54013de32cb5dc8b13a9b1190d460a5`.
Inventory prepared before source changes. This describes source configuration, not an observed deployment. No Azure state or live service was read.

## Assumptions and missing organizational inputs

The repository owns Azure networking, vault, blob storage, monitoring, optional modern Foundry accounts/projects/deployments, and configuration for an existing Gravitee platform. It does not own gateway compute, Entra registrations, license services, databases/counters, collectors or state bootstrap. No actual VM, private runner, managed identity attachment, approved models, gateway/plugin inventory, DNS forwarder, hub routes, subscription entitlement or live state access has been supplied. Existing gateway 4.13.x is a candidate reference, not verified installed compatibility. Default data grants, Foundry model creation, gateway activation and publication remain off.

Pre-change gaps: the foundation offers one combined vault/blob/telemetry grant flag; operators cannot select those privileges independently. Gateway IMDS configuration requires a topology confirmation but does not require an explicit hosting model or a separate backend RBAC review. The generic network module does not validate that every endpoint's requested DNS zone belongs to its owned zone set. These will be addressed without changing resource ownership or provider versions.

## Boundaries

Public service hostnames can resolve to private IPs through Private Link. Replacing them with PE IP addresses or `privatelink` hostnames can break TLS/authentication. Network access is not an authorization grant. Foundry account/project managed identities are not automatically attached to applications or granted access to all data.

Entra/JWKS, ARM, package distribution, VM IMDS and Gravitee management are distinct exceptions or external prerequisites. This repository must not be described as fully private or managed-identity-only end to end. Source-level controls are not evidence of live routing, DNS, SDK authentication or service availability.
