# Phase 3 preimplementation decisions

- Two user attachments are byte-identical. Base is verified remote phase2-microsoft-foundry commit d002f3e338dfd0073e11ba401ade7226fd4e6d9d. No AGENTS.md exists in the workspace/checkout. An isolated phase3-gravitee-ai-gateway worktree preserves original sources/ZIP and Phase 1/2 branches.
- Phase 2 implementation/local validation exists (75 mocked tests); Azure resources/models/endpoints are NOT deployed. Gateway integration must consume explicitly approved non-secret endpoint/deployment metadata, not fabricated live state.
- Official gravitee-io/apim 1.2.0 was returned by the Terraform Registry, installed with developer signature key 943FC12BEA201174, and its binary schema inspected. AzureRM/Terraform pins and all existing locks remain unchanged. Gravitee gets separate roots/states under gateways/.
- Requested actual server/gateway version, edition/license and plugin inventory asynchronously. No response has arrived. Reference baseline is APIM 4.13.x, NOT an assertion of installed compatibility or entitlement. Activation requires explicit matching server/gateway versions, exact plugin version inventory, confirmed Automation API/edition entitlement and operational security review. All examples remain disabled.
- Management host, organization/environment IDs, service-account access, gateway topology, managed identity, actual Phase 2 metadata and production governance inputs are not supplied. No live gateway, subscription, publishing, policy update or Azure operation will be attempted.
- Scope is a private V4 HTTP PROXY for the explicitly approved classic Azure OpenAI deployment chat/completions contract only. Other Foundry/project APIs, unified inference, MCP, agents and native LLM proxy semantics are not interchangeable and are rejected/excluded.
- Consumer authentication uses documented JWT plan configuration (Entra v2 JWKS) plus explicit issuer/audience/expiry-presence/application-role checks. Applications reference existing Entra client IDs; no DCR/client secret/API key is configured. JWT subscription association uses azp and needs runtime validation against the actual Entra token contract.
- Backend identity is a deliberately limited reference mode: documented runtime HTTP Callout to the Azure VM IMDS endpoint, requesting a token for Cognitive Services with an explicitly selected user-assigned managed identity. This is NOT imperative Terraform provisioning. Tokens remain runtime context values, never Terraform inputs/outputs. This mode requires Azure VM hosting with that identity attached and account-scoped OpenAI User RBAC from the Azure owner. It does not claim AKS workload federation, Cloud-hosted gateway, App Service or token caching support. Missing/error token conditions fail closed.
- Official Git-tree-pinned schemas verify JWT, rate-limit, quota, HTTP Callout, Interrupt, header/query transforms. Shared-policy invocation is taken from the pinned provider example. No arbitrary policy JSON inputs or invented policy IDs are accepted.
- Request rate limits/quotas are synchronous and fail closed; they are NOT LLM token limits or spend caps. Installed AI token/guardrail/MCP plugin schemas and licensing are unverified, so no fictional AI controls are generated. These gaps are explicit deployment governance limitations.
- API content/header logging and OTel payload logs are always off. Optional tracing requires explicit collector/redaction approval, disables verbose tracing and masks span attribute values. Host-wide logs/exporter setup remain external.
- Private networking/DNS/TLS/egress, IMDS availability, counter store, gateway hosting/licensing and Azure RBAC remain external prerequisites. Terraform only configures APIM via its official provider. No terraform_remote_state reads, credentials in state inputs, or API-key subscriptions.
- No apply/destroy/real provider plan runs. Offline mocks/contract checks verify configuration; they cannot prove runtime policy execution, token acquisition, route semantics, authorization, distributed limits or privacy of all host logs.
